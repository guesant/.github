# Support

If you need help with one of my projects, you are welcome to ask.

Before opening a new request, check the project's README, documentation, existing issues, and existing discussions. You do not need to understand everything before asking for help, but a little context makes it much easier for someone to help you.

## Where to ask

Use the channel that best matches what you need:

* **GitHub Discussions** for questions, usage help, configuration problems, architecture discussions, and general guidance.
* **GitHub Issues** for reproducible bugs and concrete feature requests.
* **Security reporting** for suspected vulnerabilities. Follow the instructions in `SECURITY.md` and do not disclose vulnerabilities publicly.

If Discussions are not enabled for a repository, use the most appropriate available channel described by that project.

## Asking for help

You do not need to be an expert to ask a question.

If you are stuck after reading the available documentation and searching for similar reports, ask. A useful question usually explains:

* What you are trying to accomplish.
* What you expected to happen.
* What actually happened.
* What you have already tried.
* Relevant versions, operating system, runtime, browser, or environment details.
* Relevant error messages, logs, configuration, or a minimal reproduction.

Try to describe the actual problem rather than only asking about the solution you currently have in mind. There may be a simpler or more appropriate approach.

Instead of:

> It doesn't work. Can someone help?

Prefer something like:

> I am trying to do X using Y. I expected Z, but instead I get this error. I tried A and B, and I am using version C.

You do not need to follow a rigid format. The goal is simply to provide enough information for someone else to understand the problem without having to guess.

## Logs and sensitive information

Before posting logs, screenshots, configuration files, or command output, check them for sensitive information.

Do not publish:

* Passwords.
* Access tokens.
* API keys.
* Private keys.
* Session cookies.
* Internal credentials.
* Personal or confidential information.

If you accidentally expose a credential, assume it has been compromised and rotate or revoke it.

## Bugs

If you believe you found a bug, use the repository's bug report form when one is available.

A good bug report should ideally include a reproducible example and enough environment information to distinguish a project defect from a configuration or environment-specific problem.

Questions about how something works are usually better suited to Discussions than to the issue tracker.

## Feature requests

Use the feature request form for concrete improvements or new capabilities.

If the idea is still exploratory, involves architectural tradeoffs, or would benefit from discussion before becoming an implementation request, GitHub Discussions is usually a better starting point.

## Security vulnerabilities

Do not report suspected security vulnerabilities through public Issues or Discussions.

Follow the repository's `SECURITY.md` policy and use GitHub Private Vulnerability Reporting when it is available.

## Response expectations

These projects are maintained on a best-effort basis.

Opening an issue or discussion does not guarantee an immediate response, implementation, or fix. Response times depend on availability, project priorities, the amount of information provided, and whether someone with the relevant knowledge is available.

A lack of immediate response does not mean that asking the question was inappropriate.

## Further reading

These are useful references on how to ask technical questions effectively:

* [How To Ask Questions The Smart Way](https://github.com/manoelcampos/how-to-ask-questions-the-smart-way/blob/master/README.md)
* [Como fazer perguntas no Telegram](https://telegra.ph/Como-fazer-perguntas-no-Telegram-07-21)

They are not mandatory reading. The main idea is simple: do some basic research, provide enough context, explain what you tried, and do not be afraid to ask when you are genuinely stuck.
